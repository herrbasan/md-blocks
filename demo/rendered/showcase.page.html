Aurora Desk

A showroom experience that lets visitors explore at their own pace. One screen, a clear invitation, and enough room to be curious.

This page is also a live sample of the format: every block boundary, image, and piece of data you see is authored in plain Markdown.

In GitHub or VS Code this reads as an ordinary project page with horizontal rules between its parts. In the enhanced renderer each rule is a section boundary, and the same source gains columns, cards, a gallery, and media players. Document-level data — title, tags, slideshow defaults — lives in the frontmatter above.

The block above is hand-authored: no kind, no id. A parser infers kind=image from its first node. The block below is the same content after one editor save — the editor stamped the resolved kind and a stable id. From then on, kind is authoritative: if the image stops being the first node, validation fails loud instead of silently reclassifying the block as text.

A small brief

  • Welcome visitors without requiring staff assistance.
  • Make the product understandable through direct exploration.
  • Let interested visitors continue the conversation later.

The interface should explain itself through what the visitor can do next.

A useful split

The main story gets more space than the supporting facts. On a narrow screen the source order still reads well: story first, facts second.

Explore without a script

Visitors move directly between features, compare options, and return to an overview whenever they want. The interface supports exploration rather than forcing a single sequence.

  1. Choose an area of interest.
  2. Look closer at the details.
  3. Save a useful next step.

A collection, not three separate images

A block that starts with a list of images is one gallery. An editor reorders its items without touching the surrounding structure; a generic preview shows a list of images.

When one image needs its own caption or crop, give it its own block.

The visitor journey

Three steps, shown as cards in enhanced output. The --- above opened this section; the directive on its first line gives it an id and a dark preset, and seconds is this section's own data.

1. Discover

A short overview makes the choices visible before committing to a path.

2. Explore

Details appear when they are useful. The overview stays one obvious action away.

3. Continue

The visitor leaves with a useful next step rather than an obligation to finish a form.

A good journey has an invitation, room to explore, and a clear way out.

Notes and deliberate boundaries

Warning: hidden does not mean private

Data with an explicit home

Named data has exactly two homes. Data about the document is frontmatter. Data about one section is a var inside that section. This section's seconds is independent of the visitor-journey section's seconds; nothing is inherited, nothing needs a scope flag.

A structured section value

A var and its fence are one lexical unit — nothing may come between them, and the editor moves them together.
