MD-Blocks: the `main` chrome scope + `repeat`, and a slide profile

nui-markdown now parses the `main` level the format adopted in spec v1.3: one
implicit main per document, `mb:main` as a break (a closing form does not exist —
`mb:/main` is reported and ignored), and chrome authored once per main as an
ordinary block carrying `repeat=header|footer`, repeated onto every surface a
renderer produces.

- renderer: chrome is extracted per main and emitted once, on the scope rather
  than per region. A region holding nothing but chrome is not a surface, so the
  canonical "chrome first in the main" placement cannot put a blank slide in
  front of a deck. Regions that are empty in the source are still preserved.
  Comment-only regions are empty too — a file-header comment no longer becomes one
- css: chrome strips — the first block in a slot sets the extent, later ones
  overlay it in source order
- new addon `nui-slides` + `nui-slides.css`: the presentation profile. One section
  per surface, a fixed canvas scaled to fit (`base="1280x720"`, `zoom`), chrome
  cloned per slide, derived slide numbers, focus containment via `inert`, keyboard
  navigation, and content that does not fit reported rather than cropped in silence
- fix: `markdownToHtml` rendered an image with empty alt text (`![](...)`) as
  literal source — the alt group required one character (closes #30). Media
  detection in the same file already accepted it, so the two disagreed

Spec: github.com/herrbasan/md-blocks, v1.3 §4.5 / §4.6.
